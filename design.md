# CrossCue visual and interaction system

Audience: a festival programmer comparing cultural priorities against a real timetable. The first screen states the contribution split: Qloo finds cultural connections; CrossCue checks consequences; the organizer decides.

Warm paper, ink and sharp lime form the operational identity. Terracotta music and cobalt cinema have text labels so color is never the only distinction. System sans-serif carries the working surface; Georgia italic adds restrained festival/editorial character to decision headlines. Fine rules, generous sections, compact metadata and a two-room vertical timetable establish hierarchy without decorative imagery or remote assets.

Time is spatial: the timeline positions all sessions by minutes since 14:00, with durations proportional to card height. Before/After preview leaves the saved timetable intact; previous slots are marked when moves are previewed. Session cards open their actual finite scheduling options. The side panel carries one decision at a time and compares movement counts and displacement before an explicit confirmation. The evidence inspector shows each directional query separately, exact shortlist and provenance, plus discarded alternatives. No-question is a complete outcome.

Motion personality: restrained operations UI. Signature easing cubic-bezier(.2,0,0,1), durations 120/220/320ms. Buttons respond through color and 1px press translation; panel changes enter by 5px over220ms. Loading motion is limited to a small spinner while work is pending and offers Cancel waiting. Timetable changes are represented by actual positions and previous-slot labels; animation is not required to understand them. No ambient loop, parallax or decorative layers. Reduced motion removes all spatial movement and spinner looping. This deliberately adapts the motion-design skill to the user's accessibility and task-first instructions.

Accessibility: semantic buttons/sections, labeled native dialog, skip link, visible3px focus ring, roving tab index with arrow navigation for inspector tabs, keyboard-accessible session detail, status/error announcements, readable contrast and44px touch targets. On mobile the decision comes before the timetable; the two room lanes remain visible without page overflow. API data is rendered as text; the client never constructs authority to apply a schedule.

Verification: `scripts/browser-journey.ts` exercised the actual server in desktop1440×1000 and mobile390×844 Chromium contexts. `evidence/browser-local.json` records43 passed assertions,10 axe WCAG A/AA state audits, real Qloo query provenance, source hashes and screenshots. The downloaded JSON was independently validated. Contrast defects were reproduced, retained and fixed. Preview and saved-state headings receive focus after decisions. This is local proof; the public deployment needs its own fresh browser run.
